# TwinVault Architecture — Phase 3B stable people

## Scope

Phase 1 is one vertical slice: create a meeting, record microphone audio, annotate it, stop it, persist it locally, and inspect it later. Phase 2A evolved the data boundary for multiple audio channels and timestamped transcripts. Phase 2B implements optional local system-audio capture. Phase 2C implements user-triggered, on-device transcription of a selected recording. Phase 2D enables Spanish, Catalan, and English transcription by default. Phase 2E anchors new audio files to the meeting timeline. Phase 2F adds a second local transcription implementation using WhisperKit. Phase 2G hardens system-audio finalization and makes incomplete transcript coverage inspectable. Phase 2H introduced a shared local pause detector. Phase 2I introduces explicit transcription profiles and a safe provider-routing policy. Phase 2J integrates Parakeet as an experimental, manually selected ES/EN-only profile. Phase 2K exposes model/transcription progress and cooperative cancellation. Phase 2L keeps the detector as Apple input segmentation and Whisper coverage analysis while restoring whole-recording context for WhisperKit. Phase 2M adds conservative recording-level routing from independent acoustic language evidence. Phase 2N evaluates Nemotron as an unregistered provider and rejects it as the current automatic default. Phase 2O persists conservative transcript-level evidence of possible system-audio playback leaking into the microphone and blocks identity inference from that channel. Phase 2P retries only acoustically active fast-provider coverage gaps and adds bounded explicit vocabulary prompts. Phase 2Q adds provenance and mandatory confirmation gates between diarization and stable identity. Phase 2R adds a bounded post-recording acoustic alignment boundary for the microphone and system-audio clocks. Phase 2S makes capture intent and failures durable evidence and exposes live per-channel health. Phase 2T keeps full context when Catalan dominates but uses contextual Catalan regions over a fast ES/EN baseline when Catalan is minor. Phase 2U improves quiet, brief Catalan switches. Phase 2V coordinates useful channels automatically and persists only reliable acoustic alignment evidence. Phase 2W adds segment-level acoustic playback reconciliation and a non-destructive conversation view. Phase 2X adds user-triggered offline diarization of the cleaner system-audio channel with meeting-local speaker labels. Phase 2Y adds reversible, explicit human review of those temporary clusters. Phase 2Z adds user-confirmed names scoped to one meeting. Phase 3A adds reversible transcript correction with direct playback from source timestamps. Phase 3B introduces stable local people and explicit meeting participation without biometric matching. No cloud inference or audio upload exists in the application.

## Boundaries

```text
SwiftUI Views
    │
    ▼
AppModel (use-case coordination)
    ├── MeetingRepository protocol ── JSONMeetingRepository
    ├── AudioRecordingService ── LocalAudioRecordingService
    ├── SystemAudioCaptureService ── ScreenCaptureSystemAudioService
    ├── AudioPlaybackService ── LocalAudioPlaybackService
    ├── AudioChannelAlignmentAnalyzing ── LocalAudioChannelAlignmentAnalyzer
    ├── AcousticPlaybackLeakageAnalyzing ── LocalAcousticPlaybackLeakageAnalyzer
    ├── DiarizationProvider ── FluidAudioDiarizationProvider
    └── SpeechToTextProvider ─┬─ AppleSpeechTranscriptionProvider
                              ├─ WhisperKitSpeechToTextProvider
                              ├─ ParakeetSpeechToTextProvider
                              ├─ NemotronSpeechToTextProvider (evaluation only)
                              └─ RoutingSpeechToTextProvider
        TranscriptionPolicy ───── profile → available provider + locales
                    │
                    ├── SpeechTurnDetecting ── LocalEnergySpeechTurnDetector
                    └── AcousticLanguageIdentifying
                            └── WhisperKitAcousticLanguageIdentifier
                    │
                    ▼
Domain: Meeting, MeetingNote, ImportantMoment, AudioRecordingReference,
        RecordingSession, Person, MeetingParticipant, TranscriptSegment,
        DiarizationTurn, CrossChannelTranscriptFinding,
        provider protocols
```

The domain imports Foundation only. It neither knows about SwiftUI, AVFoundation, nor persistence format. UI mutation goes through `RecordingSession`, which owns meeting-state invariants. Actor-isolated persistence serializes all disk access. AVFoundation stays behind a main-actor service because microphone authorization and recording are UI-driven platform operations.

System audio uses ScreenCaptureKit with only an `.audio` stream output. TwinVault does not register a `.screen` output, so captured video frames never enter the process or vault. The current application is excluded from its own audio capture. Audio is encoded as 48 kHz stereo AAC in a channel-specific M4A file. If ScreenCaptureKit authorization or startup fails, the meeting continues with microphone audio and surfaces a warning. An `SCStreamDelegate` reports unexpected termination immediately. Stop is idempotent, M4A finalization runs even if ScreenCaptureKit's stop call throws, sample delivery and finalization share one serial queue, and a completed file is reopened with AVFoundation before acceptance.

The application verifies `isCapturing` after system-audio startup rather than trusting a returned file reference. During recording, microphone and system audio have independent visible states. A meeting persists whether system audio was requested plus structured `AudioCaptureIssue` records for startup, interruption, and finalization failures. These warnings remain visible in meeting detail after restart. Legacy meetings default to “system audio not requested”; the migration never invents a historical failure that cannot be proven.

New microphone and system-audio references persist `meetingTimelineOffset`, measured from the meeting start to the point where each capture service reports successful startup. RecordingSession creation occurs only after microphone permission is resolved. Legacy recordings decode with no timeline anchor instead of inventing an offset. The domain can map a file-relative timestamp onto the meeting timeline when an anchor exists. This is a wall-clock startup-boundary estimate; it does not yet account for encoder priming, the first sample's presentation timestamp, device latency, or clock drift. Automatic channel fusion must wait for buffer-level calibration and fixture measurements.

Phase 2R adds post-recording acoustic calibration without changing the live capture path. `LocalAudioEnergyFingerprintExtractor` streams each file in 100 ms frames and retains only a logarithmic RMS envelope, so analysis memory grows at roughly ten scalar values per second rather than with decoded PCM size. `ChannelAlignmentEstimator` correlates bounded overlapping windows, produces timing anchors, estimates microphone delay and drift per hour, and reports confidence. Flat audio, weak matches, mismatched meetings, wrong channel roles, and unsafe paths fail closed. A positive file delay means system playback appears later in the microphone file. Phase 2W corrects that file-relative delay using both recording start offsets before it becomes a meeting-timeline estimate. Only estimates over the reliability threshold are persisted; they never delete, merge, or attribute text.

Playback uses `AVAudioPlayer` behind an async service boundary. Stored paths must be a single relative filename and are resolved only inside the vault audio directory; traversal and missing files are rejected before AVFoundation receives a URL.

`LocalEnergySpeechTurnDetector` streams 50 ms PCM windows, estimates a local noise floor, and groups active regions across pauses of at most 500 ms. This is intentionally a small replaceable VAD-like boundary, not a language detector, diarization model, or speaker identity. For Apple Speech, `LocalAudioTurnSlicer` writes lossless temporary CAF files outside the vault and deletes the whole run directory after success, failure, or cancellation. Apple translates slice-relative results back onto the original recording timeline. WhisperKit does not receive these slices; it uses the detector's intervals only for post-transcription coverage checks.

Transcription uses Apple's `SpeechAnalyzer` and `SpeechTranscriber` behind the domain-owned `SpeechToTextProvider` protocol. Every meeting stores its requested locales, defaulting to `es-ES`, `ca-ES`, and `en-US`. Because each Apple transcriber accepts one locale, the adapter resolves all three locales at runtime, installs each asset independently, and analyzes every detected speech turn with each available locale. Per-turn processing prevents one long dominant-language hypothesis from suppressing a later short language change. Successful languages still produce a persisted transcript and the output reports any skipped locale to the user. A pure selector keeps the highest-confidence hypothesis where locale results overlap. Each persisted segment records its original audio time range, source recording UUID, provider identifier, and selected locale. Re-transcribing one channel replaces only segments derived from that recording.

The selection rule is a first implementation, not an assertion that confidence scores are perfectly calibrated across languages. Its boundary and deterministic tests allow replacement without changing the domain or UI. Production readiness requires consented code-switching fixtures covering Spanish/Catalan, Spanish/English, Catalan/English, accents, overlapping speech, and silence, plus energy and latency measurements on supported Apple Silicon hardware.

WhisperKit 1.1.0 is pinned for reproducible builds and only its transcription product is linked. `WhisperKitSpeechToTextProvider` validates vault-relative audio paths and sends the original recording to its engine exactly once. `LocalWhisperKitEngine` owns the non-`Sendable` runtime inside an actor. It lazily downloads and loads Argmax's recommended `large-v3-v20240930_626MB` multilingual model only after explicit user selection, then reuses it for the process lifetime. WhisperKit's incremental file loading bounds memory and its native VAD selects decoding chunks without discarding the recording's broader context. Neither Whisper's VAD chunking nor the shared energy detector is speaker diarization.

Whisper control tokens are removed before text enters the domain. The current WhisperKit result-level language is deliberately not persisted as a segment language: mixed-language evaluation showed that it is not reliable evidence for every segment. Language labels may return later only behind a separately evaluated per-segment boundary.

WhisperKit performs one bounded recovery attempt for long timestamp gaps that contain acoustic activity. Afterwards, `TranscriptCoveragePlanner` intersects the final transcript with energy-detected speech turns and persists only uncovered active intervals of eight seconds or more as `TranscriptReviewInterval` records linked to the exact source recording. They are warnings, not claims that intelligible speech definitely exists: music and noise can also look active. Future memory extraction must treat a transcript with review intervals as incomplete evidence.

The third-party runtime is isolated behind an internal engine protocol. Unit tests substitute a deterministic fake, so CI neither accesses the network nor downloads model weights. Apple Speech remains available in the same UI for comparison and fallback. A successful new run replaces only transcript segments for the selected recording; provider provenance remains on every segment.

The UI selects a `TranscriptionProfile`, not a raw model implementation. The recommended experimental profile requests ES/CA/EN and uses `RoutingSpeechToTextProvider`; direct WhisperKit, Apple Speech, and Parakeet profiles remain explicit comparison and fallback choices. `TranscriptionPolicy` filters profiles against the providers registered at composition time and picks the recommended available profile as the deterministic default. Transcript text can never silently switch engines. Diarization is not a language router.

Automatic routing starts from recording-level acoustic evidence. `WhisperKitAcousticLanguageIdentifier` uses energy-detected speech to plan bounded language-analysis windows. Every `AcousticLanguageObservation` records its audio interval, predicted language code, and model confidence. Unsupported languages, missing evidence, detector failure, or Catalan occupying at least half of trusted speech evidence selects whole-recording WhisperKit. Confident ES/EN without Catalan selects whole-recording Parakeet.

Minority Catalan uses the optional `RegionalSpeechToTextProvider` capability. Nearby high-confidence Catalan observations are joined into one selection. The multilingual provider receives ten seconds of context on both sides and never less than twenty seconds total, but only segments centered inside the Catalan selection can replace the Parakeet baseline. This is deliberately different from the rejected strategy of decoding every small VAD turn independently. If a regional decode fails or returns no segment, fast-provider evidence remains intact and the Catalan interval is marked for review. Whole-Catalan meetings still use the original complete-file incremental WhisperKit path. Provider and source-recording provenance remain attached to every segment in a mixed result.

Language-identification windows preserve individual complete speech turns; they join only sub-minimum turns and expand a remaining short turn rather than silently dropping it. The energy detector retains its relative noise-floor calculation with a -60 dBFS lower clamp for quiet microphone speech. A confirmed Catalan region is decoded with an explicit Catalan language constraint over wide context. Parakeet's three-second evidence chunks are created from word timestamps after whole-file recognition, so this finer replacement boundary does not feed context-poor audio fragments into the ASR engine.

After a confident fast route, Parakeet compares its timestamped output only with acoustically active speech turns. If it leaves an uncovered interval of at least eight seconds, `RoutingSpeechToTextProvider` performs one whole-recording WhisperKit recovery pass but selects only Whisper segments centered inside those review intervals. This retains model context while bounding what can replace missing evidence. Remaining uncovered portions stay persisted for review; repair failure preserves the original fast output. Mixed outputs keep each segment's real provider identifier.

`TranscriptionRequest.contextualTerms` is a bounded, deduplicated list of explicit local terms. `AppModel` currently supplies only the meeting title written by the user. WhisperKit tokenizes it into decoder prompt tokens for both primary and gap-repair passes. The prompt is guidance, not evidence, and no fuzzy post-processing rewrites transcript text. Parakeet ignores the terms until its separate CTC vocabulary path has timestamps and accuracy benchmark coverage.

`ParakeetSpeechToTextProvider` is available through the explicit experimental ES/EN profile and through a confident ES/EN automatic decision. It performs a second provider-level allowlist check and rejects Catalan or any other configured language before file access and inference. FluidAudio 0.17.4 and Parakeet v3 are pinned to the versions used in the feasibility benchmarks. The model is lazily downloaded into the vault's controlled models directory only when needed. The runtime lives behind an actor and test-only engines avoid model downloads. Word timestamps are grouped at acoustic pauses or bounded duration/word counts to create evidence-sized segments; no per-segment language is asserted. Long uncovered intervals use the same review-warning policy as WhisperKit.

`NemotronSpeechToTextProvider` is an evaluation-only FluidAudio adapter for automatic, forced-Spanish, and forced-English runs. It performs the same path and locale validation and stores recording/provider/time provenance, but it is not registered with `TranscriptionPolicy` or exposed in the UI. The eight-case comparison showed worse ES/EN accuracy than Parakeet and worse Catalan accuracy than WhisperKit. Its automatic mode also returned no detected language for several successful transcripts, so it cannot replace the independent acoustic language identifier. FluidAudio's source is Apache 2.0, while the downloaded converted model requires a separate distribution-license review before any product release.

`CrossChannelTranscriptReconciler` is a pure domain service run whenever either channel's transcript is replaced. It requires timeline anchors plus strong temporal overlap and accepts either strong ordered-token coverage or an independently measured aligned acoustic correlation. The finding links the microphone segment to the exact system-audio segment IDs and persists text, acoustic, and timing scores. Weak evidence fails closed. `MeetingConversationTranscript` is a computed view that hides flagged microphone duplicates while retaining system evidence; `Raw Channels` exposes every original segment. Nothing is deleted, copied, or claimed as fact. `SpeakerAttributionPolicy` blocks any flagged microphone segment and requires independent speaker-identification evidence for every other segment. Therefore “microphone” means only the local capture channel, never “me.”

Diarization remains a separate provider boundary downstream of audio capture and never performs language routing. Phase 2X uses FluidAudio's offline Community-1/VBx pipeline only after the user presses **Detect Speakers**. A local AVFoundation preflight rejects missing, empty, or structurally incomplete audio before model preparation. The primary clustering uses FluidAudio's calibrated threshold. A merge-tolerant stability clustering reuses the same prepared segmentation and embeddings, avoiding a second Core ML inference pass. It affects output only when a cluster is at most three seconds and 12% of detected speech, a stable pass maps at least 80% of it onto a non-overlapping speaker with at least ten seconds and three times its duration, and both clusters share the same stability identity. This guards against short end-of-utterance fragmentation without deleting a short voice that remains distinct or overlaps another speaker. The first valid run downloads its Core ML assets into the vault model directory; the recording itself stays local. This increment deliberately processes only system audio, because microphone playback leakage could otherwise create a false local-speaker cluster. Turns retain file-relative time, matching transcript evidence, and are stored with source-recording and provider provenance. The recording reference supplies the meeting-timeline anchor whenever cross-channel comparison is needed. Raw model clusters are renamed by first appearance to meeting-local `speaker-1`, `speaker-2`, and so on.

`TranscriptSpeakerAttribution` joins transcript and diarization evidence only at presentation time by recording ID and maximum temporal overlap. It does not rewrite transcript evidence. A label such as “Speaker 1” is valid only inside one meeting and is not a person. A later speaker-identification provider may propose a match with an explicit basis. `SpeakerIdentityEvidenceGate` classifies all model and local-voice-profile matches as inferences requiring confirmation, treats unknown as unknown, and accepts `CONFIRMED` only from explicit user action. Any turn overlapping a `possiblePlaybackLeakage` microphone segment is blocked before identity, regardless of confidence. No biometric voice profile or stable third-party identity is created or persisted in this phase.

Phase 2Y persists `SpeakerClusterCorrection` separately from raw `DiarizationTurn` evidence. A user may mark one meeting-local cluster as the same speaker as another; presentation resolves that mapping without rewriting model output. Each correction retains meeting, recording, source cluster, canonical cluster, confirmation basis, and time. Cycles are rejected, corrections are reversible, and a fresh diarization run clears corrections for that recording because its cluster labels may have changed. This is cluster review only: it does not assign a person's name or create a voice profile.

Phase 2Z persists a `MeetingSpeakerLabel` only after explicit user entry. It links a display name to one canonical temporary cluster and retains meeting, recording, confirmation basis, and time. The transcript displays both the name and technical cluster label so provenance remains visible. Labels are editable and removable, never become cross-meeting `Person` identities, and are cleared with their cluster corrections when diarization is rerun. Merging two differently named clusters fails closed until the conflicting label is removed.

Phase 3A keeps generated `TranscriptSegment` evidence immutable and stores each explicit edit as a separate `TranscriptSegmentCorrection`. The correction snapshots the original text and retains segment, meeting, corrected text, confirmation basis, and time. Presentation shows corrected and original text together, plus provider, channel, time range, and confirmation state. Playback seeks the original recording to the segment start. Undo removes only the correction. Re-transcribing or clearing a channel removes corrections linked to the replaced segment UUIDs so stale edits cannot attach to new evidence.

Phase 3B separates stable people from temporary acoustic speakers. `Person` is a workspace-local identity with a stable UUID. `MeetingParticipant` links that person to one meeting, while `MeetingSpeakerPersonAssignment` records the user's explicit confirmation that one reviewed temporary cluster represents that participant. Diarization never creates a person and no voice embedding, biometric profile, or cross-meeting automatic match exists. Re-running diarization invalidates cluster assignments but retains attendance; unlinking a cluster removes an unused participant link but does not delete the stable person. The repository saves a newly created person and its meeting assignment in one atomic JSON update. Store schema 15 decodes older stores with an empty people collection.

`TranscriptionRequest` carries an optional `Sendable` progress sink. Providers report semantic stages without coupling the domain to SwiftUI. FluidAudio supplies Parakeet's determinate download fraction; WhisperKit and Apple Speech report indeterminate preparation/loading stages because their adapters cannot obtain a trustworthy equivalent fraction. `AppModel` owns the single active task and cancellation boundary. It checks cancellation before replacing transcript data, suppresses cancellation as a user-requested error, and keeps all previously persisted evidence unchanged. Provider cancellation is cooperative, so a Core ML call may return only after its current non-interruptible operation finishes.

## ADR-001: versioned JSON before SQLite

Phase 1 has four small aggregate types and no relational query workload. A schema-versioned JSON document with atomic replacement is transparent, testable, backup-friendly, and avoids a dependency or premature migration system. Large audio files are never placed in metadata.

The cost is whole-document reads/writes and weak multi-process support. `MeetingRepository` makes the choice reversible. Schema 2 migrates Phase 1's single microphone reference into a channel-aware array; schema 3 adds transcript segments; schema 4 stores the meeting's requested transcription locales; schema 5 adds optional audio timeline anchors; schema 6 persists transcript review intervals; schema 7 persists cross-channel playback-leakage findings; schema 8 persists system-audio capture intent and issues; schema 9 persists reliable channel alignment; schema 10 adds optional acoustic similarity to leakage findings; schema 11 adds diarization turns; schema 12 adds user-confirmed speaker-cluster corrections; schema 13 adds meeting-local speaker labels; schema 14 adds user-confirmed transcript corrections. Older meetings decode to the three default locales, an unknown audio offset, and no invented review, leakage, alignment, capture-failure, speaker-turn, speaker-correction, speaker-label, or transcript-correction findings. JSON remains acceptable for short development fixtures, but move to SQLite before storing production-volume transcripts. Domain/UI code must not change during that migration.

## Data integrity and provenance

- UUIDs are stable identifiers.
- Notes, important moments, and audio references carry their parent `meetingID`.
- Transcript segments identify the exact source recording, provider, locale, and audio time range.
- New audio references record their approximate offset on the meeting timeline; legacy offsets remain explicitly unknown.
- Important moments store elapsed source time, enabling later audio/transcript evidence links.
- Paths stored in metadata are relative to the controlled audio directory.
- Meeting completion is idempotent and end time cannot precede start time.
- Cross-channel findings retain both microphone and system transcript IDs and remain hypotheses, not speaker identities.
- Reliable channel-alignment estimates retain their acoustic anchors, confidence, delay, and drift; unavailable or weak estimates remain explicitly absent.
- Store schema version is validated before decoding is accepted.

This is provenance scaffolding, not the future Memory model. Facts, inferences, twins, and biometric identity are intentionally absent.

## Privacy and security posture

There is no external inference service. Microphone access is requested only when the user starts a meeting. `AssetInventory` may download a language model from Apple at the user's first Apple Speech request. Choosing WhisperKit or experimental Parakeet for the first time downloads public Core ML model assets from their configured model repositories into the local vault. Providers never upload meeting audio. Metadata and audio live under Application Support, and metadata uses atomic writes. The macOS application does not claim application-level encryption at rest: it currently inherits filesystem protection such as FileVault when enabled. Keychain-managed workspace keys, Apple cryptographic APIs, audit logs, export, retention, and propagation-aware deletion require a deliberate later phase.

## Concurrency

Types crossing boundaries conform to `Sendable`. The repository is an actor. Presentation and AVFoundation services are `@MainActor`. Async repository calls prevent disk work APIs from leaking callbacks into views. Strict Swift 6 checking is enabled by the toolchain.
